# Apple 直营店自提购买助手 — 自动演练与页面回放候选

> **重要：当前可运行的购买流程仍是离线演练。** 演练中的商品、门店、日期、价格、时段均为 **FAKE 虚构数据**；界面里的“模拟官网”及其 `mock-v0` 契约是本项目**自行虚构**的，**不是** Apple 的页面或接口。离线程序不访问苹果官网。另有单独、明确执行才联网的**公开入口只读预检**（C-004），仅识别目录与预检阻断；它不是库存监控或真实购买适配器。两者均不能产生真实订单、付款或时段占用。真实浏览器结账执行器已有待复核候选，尚未安装或完成官网联调，**真实正式模式不可用**。10 月 2 日另由 Codex 在用户 Chrome 按明确授权完成一张 Pro 未付款订单；那次浏览器工具实跑不等于程序已能一键下单。

离线演练、公开入口预检与末档规则已获得实际双方有限范围同意，C-007-R1 的修复已通过 Codex 独立验收。10 月 2 日晚已取得真实 Claude 复审：C-010/C-011 仅部分范围同意，C-012 购买执行器因门店识别和重复加购问题被退回。Claude 修复后再次遇到额度限制，Codex 已按授权补齐修复；目前 351 项测试通过，仍待 Claude 对最新准确改动复核。官网订单查询的新登录路径已正确识别为人工登录阻断。当前证据与恢复点见 [docs/status.md](docs/status.md)。

## 官网执行器的当前进展

`web/checkout-connector` 已有正常官网控件执行代码，尚未安装或完成真实结账联调。已补入固定的“不折抵换购、不加 AppleCare+”条件，以及单独的“公开配置校验”：一次开始依次完成选配，停在添加到购物袋之前，不写入购买任务。实际 Chrome 离线原生控件验证通过；API 传输与官网地址在该验证中明确模拟。官网 Pro 页面也已用正常控件验证这两个选项会启用加购，无须强开按钮。这些结果不代表程序已经能自动创建官网订单。[电脑执行说明](docs/checkout-chrome-runbook.md)

## 电脑一键完整 DOM 演练（当前功能候选）

在项目目录执行：

```powershell
node src/dom-demo.ts --task-dir .local/dom-desktop
```

用你电脑的 Chrome 打开终端打印的本机地址，核对 **FAKE** 计划后点一次 **开始自动模拟下单**。程序实际操作页面原生控件：加购 → 到店自提 → 第一天末档拒绝 → 最新列表选第二天末档再拒绝 → 第三天末档接受 → 填虚构信息 → 选择模拟支付宝 → 最终点击一次 → 另一次查单核对未付款模拟订单。没有在线模型参与这些运行决策。

当前整套 351 项测试通过；C-010 当时的代码在实际 Chrome 单次测得 291ms，仅为本机虚构页面，不代表官网速度。提交回复丢失只做查单；超价、控件换新、订单条件不符和结果不明均停止。记录重启后保留，已有运行禁止新建订单；不提供删除历史后重试的入口。[运行与限制](docs/desktop-dom-runbook.md)

普通 Chrome 的只读连接组件在 `web/chrome-connector/`，已验证当前官网公开配置采集逻辑，**尚未安装或获得独立运行权限**。它只申请本人点击后临时读取当前公共商品页，不能操作官网或结账。真实自动下单适配仍未完成。

## 它演示了什么

在本机浏览器里，一键跑完核心痛点流程，全程无需人工：

观察时段列表 → 自动选择计划内优先级最高的时段 → 被模拟官网**明确拒绝** → 取**最新**列表（新代次、新引用）→ 自动改选另一个授权时段 → 被**明确接受** → 自动继续结账 → 到达模拟付款前终点（无正式授权时绝不提交）。

界面实时显示：当前步骤、原因、候选时段（按你的计划优先级）、拒绝/刷新次数、最后有效观察时间、在途或“结果不明”的操作、模拟官网状态、脱敏追踪日志；并提供 暂停 / 恢复 / 人工接管 / 停止。

## 安装

无需安装任何依赖（零运行时依赖，未使用 npm 包，界面不加载任何外部资源）。只需要 **Node.js 24.16.0 或更高版本**。

```
node --version   # 应为 v24.16.0 或更高
```

## 运行浏览器界面

```
node src/cli.ts app
```

在项目目录执行。终端会打印 `请在本机浏览器打开：http://127.0.0.1:<端口>/`。用本机浏览器打开即可（服务只监听 `127.0.0.1`，局域网其他设备无法访问）。按 `Ctrl+C` 退出；程序先暂停、停止旧执行循环，再释放任务锁。再次启动后可“恢复运行”；暂停状态仍保留，需要明确点击恢复。

### 基本演练（无需 JSON）

1. 打开页面。第一个打开的标签页会自动成为**控制页**；之后再打开的标签页显示“本页只读”，不能开始或恢复，但可以 **暂停 / 人工接管 / 停止**。控制页关闭或刷新后，只读页会出现“由本页控制”按钮，需你明确点击。
2. 在“开始一次演练”里选一个示例：
   - **基础演练**：首选时段被明确拒绝 → 用最新列表改选 → 被接受 → 继续到模拟付款前；
   - **三日末档演练**：时段形状参照历史 iPhone 18 Pro 页面（日期 + 15 分钟时段，10:00–10:15 起）。门店、日期、容量和结果全部是 **FAKE**。第 1 天最晚时段被拒并从列表消失后，**不回退**到当天更早时段，改选第 2 天最晚；再被拒后选第 3 天最晚（第 3 天虚构为 20:45–21:00 结束，用于说明最晚时间取自列表），被接受后继续到付款前。
3. 如果示例需要自己的计划，先点 **载入此示例计划**：它会保存为**新的计划版本**，旧版本保留，正在运行的任务仍绑定原版本；当前计划不是 FAKE 时不会载入。核对页面上的计划摘要后点 **开始演练**。
4. 页面会显示：当前步骤、**下一步**该做什么、最近选择/已接受的日期和时间、在途操作、最近经过（选择、拒绝、接受、终点）。

**怎样算成功**：显示“已到达模拟付款前步骤（演练终点，未提交任何订单）”。这只说明本机程序的流程正确，**不是**真实购买、预约或可以开售的证明。

**安全恢复**：

- 暂停、人工接管、停止只阻止**新**动作；已经发出的操作不会被撤回，程序会继续核实它的结果。
- 程序退出或崩溃后重新启动，页面会显示“上次运行（历史结果）”。若有未完成运行，点 **恢复运行**：先从日志只读核实，结果不明的操作**绝不重发**。
- 出现红框的“持久证据异常 / 执行器错误 / 购买台账”提示时，按提示人工检查，不要删除任务目录、日志或台账，也不要换新任务重试。

### 高级详情（默认折叠）

任务/运行编号、计划哈希、完整诊断日志、模拟官网内部状态、其他场景（`submit-confirm`：配合模拟正式授权提交一单**模拟**订单；`submit-unknown`：模拟提交结果不明，验证绝不再次提交）、计划 JSON 编辑都在页面底部的“高级详情”里。

- **修改计划**：编辑 JSON 后点 **保存计划**。每次保存生成新版本；**已开始的运行仍绑定它开始时的版本**。
- **模拟正式授权**（默认关闭）：勾选“我已核对当前计划版本”，输入确认语，点 **启用一次**。它只对**下一次运行**、**当前计划版本**、**30 分钟内**有效，整个任务只能启用一次，只能向本机模拟官网提交模拟订单。启用或使用后，主页面顶部会一直显示红框提醒。

### 真实购买还缺什么

真实苹果结账尚未接入程序。10 月 2 日 Pro 实跑看到了自提日期/时段、选择后继续和账户内未付款订单，但没有遇到真实时段拒绝，也未付款。官网明确提示取货日期待付款完成后确定；控件选中和继续成功不能当作时段保留。Duo 的真实列表、拒绝、占用和订单机制仍需独立验证。页面回放仅在完整合成样本中绑定最初至多三个日期；真实列表完整性和年份缺失时仍停止。Pro 的时段形状不代表 Duo 固定日期、数量、间隔或末档。

## 开售页面回放（C-007 候选）

在**同一个标签页**中打开“开售页面回放”：点演练页面高级详情里的链接，或把地址栏路径改成 `/launch`。同一任务同一时间只有一个标签页能控制；另开的第二个标签页只读，不能操作。选一个合成场景，点“加载样本并观察”：页面从实际 DOM 读取原生/角色控件、选中、禁用和可见状态，再计算离线候选。维护、未开售、加载未完成、网络失败、503、限流、登录和条款分别显示。

第一次看到完整日期列表时，最先出现、可见且可选的至多三个日期即被冻结（含计划外日期时也冻结，并交本人处理）；冻结范围和已经看到的末档写入原任务目录，页面改版、暂停和重启不会滚动日期或放宽末档。合成样本由本机服务签发给控制中的标签页，只能用一次；改计划后旧记录显示“属于计划 vN”，不会改绑。结果不明时优先核实，恢复后的页面不能触发重发。导入的观察只在内存中预览，不保存、不产生候选；不要导入账号、证件或付款资料。本页不访问 Apple。

CLI 会回放 20 个合成 AST 场景并验证结果不明状态。实际浏览器 DOM 的检查另行记录，CLI 不冒充浏览器或官网证据。首次执行后保留产生的任务目录；若提示待核实，不要删历史或换目录重试同一购买意图。新测试使用另一个明确标注的虚构测试任务。

详见 [页面回放说明](docs/launch-replay-runbook.md) 与 [真实 Pro 验证](docs/reviews/Pro-Chrome-unpaid-pilot-20261002.md)。

## 官网公开入口只读预检（C-004）

```powershell
node entry/cli.ts inspect
node entry/cli.ts inspect --example --json
```

每次仅向已核实的 Duo 官方公开目录或示例规格 URL 发一次普通 GET，8 秒超时、最多 2 MiB，不携带 Cookie/账号/付款信息，不跟随重定向，不自动重试。示例规格仅用于读取公开页面，并非替你选择购买条件。

读取公开 HTML 只能识别目录标题和明示日期；它不执行页面脚本，不能据此判断动态按钮、门店库存或自提时段。读取失败、未知结构、认证、拒绝访问、限流和重定向会分别报告并停止；HTTP 200 本身不表示页面已识别。

可以离线导入**仅包含公开语义字段**的脱敏浏览器观察：

```powershell
node entry/cli.ts inspect --snapshot <公开页面观察.json> --json
```

观察格式为 `applebuy-public-dom/v1`；结构见 [只读预检说明](docs/reviews/C-004.md)。程序校验目标与字段，拒绝额外字段、矛盾控件、未完成加载和超过 5 分钟的观察。来源声明还需独立核实。这个命令不会自动连接或控制你的浏览器；实际浏览器观察由授权的只读工具另行获取。不得导入账户、Cookie、支付、个人信息或原始认证请求。

JSON 中 `purchaseReady` 与 `realMutationsAvailable` 恒为 `false`。退出码 0 仅代表识别了某个入口观察，**不是可购买**；真实计划并未加载，商品与门店绑定、Duo 时段/拒绝/占用/订单确认机制仍未验证。此预检是独立程序，离线演练应用保持原有网络拦截且不导入它。

## 购买计划配置

| 字段 | 含义 |
| --- | --- |
| `fake` | `true` 表示虚构演练计划（界面会醒目标注 FAKE） |
| `fulfillment` | 只能是 `pickup`（直营店自提） |
| `quantity` | 只能是 `1` |
| `maxTotalCny` | 含税总价上限（元）；页面总价超过即拦截 |
| `products` | 授权的商品规格（型号/容量/颜色），可多个备选 |
| `stores` | 授权门店，`primary` 首选 / `backup` 备选 |
| `dates` | 授权日期（`YYYY-MM-DD`） |
| `slotSelection` | 可选 `last-offered-per-store-date`：每个授权门店／日期只考虑完整最新列表的最后一档；日期递增、`priority` 首项必须为 `date`。末档不可选、被拒或超出到店范围时不自动改选当天较早时段。省略保留原有较早时段策略 |
| `windows` | 授权时间窗；整个时段必须落在某个窗口内 |
| `arrival` | 可到店时间范围；整个时段必须落在该范围内 |
| `priority` | 排序优先级，例如 `["date","store","window"]`；不按页面显示顺序 |
| `bounds` | 拒绝次数、刷新次数、单时段尝试次数、最小刷新间隔、查询失败次数、结果核实次数的上限（不能超过内置硬上限） |
| `paymentMethodLabel` | 付款方式**标签**（只作提示，不保存任何付款信息） |

缺失或不合法配置会被拒绝保存。运行开始后计划被**冻结绑定**（以计划哈希校验），之后的编辑只影响未来主动启动的运行，不会扩大已有运行的授权。真实规格与 SKU 对应关系仍需要当前官网证据，格式检查不证明这种绑定。

| 文件 | 作用 |

## 安全设计（摘要）

- **唯一执行进程**：按实际任务目录（含 Windows 目录别名）由操作系统级命名管道独占。第二个进程启动会被拒绝；**状态读取超时或心跳过期都不算退出**。正常退出先使执行器停止写入，再释放锁；异常退出由操作系统释放锁。不会结束任何其他进程。
- **同一决策核心**：界面、命令行演练、测试与基准使用同一个引擎和运行器，没有另一套演示算法。
- **发送前复核**：每个改变状态的操作先写“准备”记录，发送前再复核（暂停/接管/挑战/价格与计划/最新列表/正式授权/购买台账），通过才写“发送”记录；否则记录“取消（从未到达模拟官网）”。
- **同一时间只有一个在途操作**；结果不明时只做只读核实，**绝不自动重发**。
- **失败即关闭**：任务身份、台账、日志缺失／无法读取／损坏或发现未登记运行证据时，拒绝新的运行、授权与发送，保留原文件。空台账也会与所有运行日志比对，不能清除未知购买结果。页面分别说明实际异常文件，日志不可读不会误称完整台账损坏。部分旧文件恢复仍留下独立证据时会阻断；同时回滚所有证据无法检测。已发送操作只能先核实，证据丢失不是重试理由。
- **状态来源**：重启后显示已校验日志的历史事实，并标明尚未重新观察；旧列表不作为候选。运行目标使用该运行绑定的计划，编辑区可以保存下一次运行的计划。
- **本机服务防护**：只监听 `127.0.0.1`；校验 Host（防 DNS 重绑定）、Origin、会话令牌与 JSON 类型；严格内容安全策略（CSP），只加载本地脚本；全进程拦截非本机网络访问。
- **真实适配器**：不存在。真实正式模式在界面中显示为“不可用”。

## 常见问题

- **“无法成为该任务的执行进程：held”**：该任务已有执行进程（可能在另一个终端）。用 `app-status` 查看；如显示 `timeout`，说明它仍持有任务锁，只是响应慢——请等待或在原终端退出它，**不要**删除任务目录。
- **“上一个执行进程异常退出”**：说明上次未正常关闭。若有未完成运行，界面会提示，点击 **恢复运行**：程序先从日志恢复，结果不明的操作只做只读核实，不会重发。
- **“不能开始新运行：……购买台账已有最终提交记录”**：本任务此前发生过（模拟）最终提交（可能结果不明）。本任务不会再提交；请人工核验。修改计划、重启或换浏览器标签页都不会解除。
- **“任务文件缺失但存在历史数据”／“任务文件校验失败”／“持久证据不一致”**：完整保留任务目录，人工核对提示中的任务、台账、运行日志和进程记录，以及独立的权威订单状态。不要删除历史、清空台账或换新任务目录重试同一次购买意图；程序没有已审查的自动解除限制操作。
- **运行已保存但第一条日志尚未写入就中断**：即使实际未发送，也无法与发送后日志丢失区分，必须保守阻断，按上述人工调查处理。
- **日志无法读取／初始化或所有权记录写入失败**：仍保留证据并停止。正常显示具体日志原因；初始化失败会释放已取得的任务锁，退出记录写入失败也释放锁但不伪造正常退出。先人工检查，不能把文件读取失败当作没有提交过。
- **“另一个标签页正在控制此任务：本页只读”**：关闭或刷新控制页（其事件连接断开后控制权自动释放），再在本页点击“由本页控制”。
- **显示“已达重试/刷新上限”**：表示达到有限上限，**不代表无货**。
- **显示“需要人工接管”/“需人工核验”**：出现验证挑战、限流、登录过期、页面无法识别、与计划不符或结果不明时，程序主动退让，由你本人处理。
