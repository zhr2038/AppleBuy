# Apple 直营店自提购买助手 — 离线演练与官网只读预检候选

> **重要：购买程序当前只有离线演练。** 演练中的商品、门店、日期、价格、时段均为 **FAKE 虚构数据**；界面里的“模拟官网”及其 `mock-v0` 契约是本项目**自行虚构**的，**不是** Apple 的页面或接口。离线程序不访问苹果官网。另有单独、明确执行才联网的**公开入口只读预检**（C-004），仅识别目录与预检阻断；它不是库存监控或真实购买适配器。两者均不能产生真实订单、付款或时段占用。真实结账与时段契约**尚未验证**。**真实正式模式不可用。**

C-002 已独立验收。C-003 由 Claude 实际实现到额度耗尽后，按用户授权由 Codex 接手修复并测试；C-004 的只读预检亦由 Codex 在额度不足期间实现。**Claude 对接手改动的交叉审查尚未完成，双方尚未达成一致，C-003/C-004 均尚未最终验收**。当前证据与恢复点见 [docs/status.md](docs/status.md)。

## 它演示了什么

在本机浏览器里，一键跑完核心痛点流程，全程无需人工：

观察时段列表 → 自动选择计划内优先级最高的时段 → 被模拟官网**明确拒绝** → 取**最新**列表（新代次、新引用）→ 自动改选另一个授权时段 → 被**明确接受** → 自动继续结账 → 到达模拟付款前终点（无正式授权时绝不提交）。

界面实时显示：当前步骤、原因、候选时段（按你的计划优先级）、拒绝/刷新次数、最后有效观察时间、在途或“结果不明”的操作、模拟官网状态、脱敏追踪日志；并提供 暂停 / 恢复 / 人工接管 / 停止。

## 安装

无需安装任何依赖（零运行时依赖，未使用 npm 包，界面不加载任何外部资源）。只需要 **Node.js 24.16.0 或更高版本**。

```
node --version   # 应为 v24.16.0 或更高
```

## 运行浏览器界面

```
node src/cli.ts app
```

在项目目录执行。终端会打印 `请在本机浏览器打开：http://127.0.0.1:<端口>/`。用本机浏览器打开即可（服务只监听 `127.0.0.1`，局域网其他设备无法访问）。按 `Ctrl+C` 退出；程序先暂停、停止旧执行循环，再释放任务锁。再次启动后可“恢复运行”；暂停状态仍保留，需要明确点击恢复。

操作步骤：

1. 点击 **获取控制权**（同一时间只有一个标签页能开始/恢复/改计划；其他标签页为只读，但任何已打开的标签页都可以 **暂停 / 人工接管 / 停止**）。
2. 在“模拟官网场景”里选择：
   - `refuse-then-accept`：首选时段被拒 → 新列表重选 → 接受 → 自动继续到模拟付款前（默认演示）；
   - `submit-confirm`：配合“模拟正式授权”提交一单**模拟**订单；
   - `submit-unknown`：模拟最终提交结果不明（验证“绝不再次提交”）。
3. 点击 **开始自动演练**。运行中可随时 **暂停**、**恢复（先重新观察）**、**人工接管**、**停止**。
4. 需要修改计划时，在“购买计划”文本框中编辑 JSON 后点击 **保存计划**。每次保存生成新版本；**已开始的运行仍绑定它开始时的版本**，新版本只用于之后的新运行。
5. **模拟正式授权**（默认关闭）：勾选“我已核对当前计划版本”，输入界面提示的确认语，点击 **启用一次**。它只对**下一次运行**、**当前计划版本**、**30 分钟内**有效，且整个任务只能启用一次；过期、计划被改动、被重复使用都会阻断提交。它只能向本机模拟官网提交模拟订单。

### 命令行参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--task-dir <目录>` | `.local/task` | 任务目录：保存任务身份、计划版本、运行日志、购买台账、执行进程记录、模拟官网状态 |
| `--plan <文件>` | `examples/plan.fake.json` | **仅在任务首次创建时**作为第 1 版计划；之后以任务目录中保存的版本为准 |
| `--port <端口>` | `0`（自动选择空闲端口） | 本机监听端口 |
| `--latency-ms <毫秒>` | `500` | 模拟官网每次回复的**人为模拟延迟**（不代表苹果网络） |
| `--recover` | — | 启动后立即“恢复运行”（与界面按钮相同） |
| `--auto-start <场景>` | — | 启动后立即开始指定场景 |

查询某个任务目录是否已有执行进程（只读，不会抢占）：

```
node src/cli.ts app-status --task-dir .local/task
```

结果：`replied`（存活并回复）、`timeout`（仍持有任务锁但读取超时——**仍视为存活**）、`gone`（没有进程持有该任务）、`error`（读取失败，不视为已退出）。

## 官网公开入口只读预检（C-004）

```powershell
node entry/cli.ts inspect
node entry/cli.ts inspect --example --json
```

每次仅向已核实的 Duo 官方公开目录或示例规格 URL 发一次普通 GET，8 秒超时、最多 2 MiB，不携带 Cookie/账号/付款信息，不跟随重定向，不自动重试。示例规格仅用于读取公开页面，并非替你选择购买条件。

读取公开 HTML 只能识别目录标题和明示日期；它不执行页面脚本，不能据此判断动态按钮、门店库存或自提时段。读取失败、未知结构、认证、拒绝访问、限流和重定向会分别报告并停止；HTTP 200 本身不表示页面已识别。

可以离线导入**仅包含公开语义字段**的脱敏浏览器观察：

```powershell
node entry/cli.ts inspect --snapshot <公开页面观察.json> --json
```

观察格式为 `applebuy-public-dom/v1`；结构见 [只读预检说明](docs/reviews/C-004.md)。程序校验目标与字段，拒绝额外字段、矛盾控件、未完成加载和超过 5 分钟的观察。来源声明还需独立核实。这个命令不会自动连接或控制你的浏览器；实际浏览器观察由授权的只读工具另行获取。不得导入账户、Cookie、支付、个人信息或原始认证请求。

JSON 中 `purchaseReady` 与 `realMutationsAvailable` 恒为 `false`。退出码 0 仅代表识别了某个入口观察，**不是可购买**；真实计划并未加载，商品与门店绑定、Duo 时段/拒绝/占用/订单确认机制仍未验证。此预检是独立程序，离线演练应用保持原有网络拦截且不导入它。

## 购买计划配置

| 字段 | 含义 |
| --- | --- |
| `fake` | `true` 表示虚构演练计划（界面会醒目标注 FAKE） |
| `fulfillment` | 只能是 `pickup`（直营店自提） |
| `quantity` | 只能是 `1` |
| `maxTotalCny` | 含税总价上限（元）；页面总价超过即拦截 |
| `products` | 授权的商品规格（型号/容量/颜色），可多个备选 |
| `stores` | 授权门店，`primary` 首选 / `backup` 备选 |
| `dates` | 授权日期（`YYYY-MM-DD`） |
| `windows` | 授权时间窗；整个时段必须落在某个窗口内 |
| `arrival` | 可到店时间范围；整个时段必须落在该范围内 |
| `priority` | 排序优先级，例如 `["date","store","window"]`；不按页面显示顺序 |
| `bounds` | 拒绝次数、刷新次数、单时段尝试次数、最小刷新间隔、查询失败次数、结果核实次数的上限（不能超过内置硬上限） |
| `paymentMethodLabel` | 付款方式**标签**（只作提示，不保存任何付款信息） |

缺失或不合法配置会被拒绝保存。运行开始后计划被**冻结绑定**（以计划哈希校验），之后的编辑只影响未来主动启动的运行，不会扩大已有运行的授权。真实规格与 SKU 对应关系仍需要当前官网证据，格式检查不证明这种绑定。

## 任务目录里有什么

| 文件 | 作用 |
| --- | --- |
| `task.json` | 任务身份（购买身份）、全部计划版本、每次运行绑定的版本与授权、模拟正式授权记录 |

## 安全设计（摘要）

- **唯一执行进程**：按实际任务目录（含 Windows 目录别名）由操作系统级命名管道独占。第二个进程启动会被拒绝；**状态读取超时或心跳过期都不算退出**。正常退出先使执行器停止写入，再释放锁；异常退出由操作系统释放锁。不会结束任何其他进程。
- **同一决策核心**：界面、命令行演练、测试与基准使用同一个引擎和运行器，没有另一套演示算法。
- **发送前复核**：每个改变状态的操作先写“准备”记录，发送前再复核（暂停/接管/挑战/价格与计划/最新列表/正式授权/购买台账），通过才写“发送”记录；否则记录“取消（从未到达模拟官网）”。
- **同一时间只有一个在途操作**；结果不明时只做只读核实，**绝不自动重发**。
- **失败即关闭**：任务身份、台账、日志缺失或损坏时拒绝新的运行，保留现有证据。台账即使变成合法的空列表，也会与所有运行日志中的最终提交记录比对，不能清除未知购买结果。已发送操作的恢复只做核实；缺失/损坏文件不能作为重试购买的理由。
- **状态来源**：重启后显示已校验日志的历史事实，并标明尚未重新观察；旧列表不作为候选。运行目标使用该运行绑定的计划，编辑区可以保存下一次运行的计划。
- **本机服务防护**：只监听 `127.0.0.1`；校验 Host（防 DNS 重绑定）、Origin、会话令牌与 JSON 类型；严格内容安全策略（CSP），只加载本地脚本；全进程拦截非本机网络访问。
- **真实适配器**：不存在。真实正式模式在界面中显示为“不可用”。

## 常见问题

- **“无法成为该任务的执行进程：held”**：该任务已有执行进程（可能在另一个终端）。用 `app-status` 查看；如显示 `timeout`，说明它仍持有任务锁，只是响应慢——请等待或在原终端退出它，**不要**删除任务目录。
- **“上一个执行进程异常退出”**：说明上次未正常关闭。若有未完成运行，界面会提示，点击 **恢复运行**：程序先从日志恢复，结果不明的操作只做只读核实，不会重发。
- **“不能开始新运行：……购买台账已有最终提交记录”**：本任务此前发生过（模拟）最终提交（可能结果不明）。本任务不会再提交；请人工核验。修改计划、重启或换浏览器标签页都不会解除。
- **“任务文件缺失但存在历史数据”/“任务文件校验失败”**：程序拒绝新建身份或覆盖文件。请人工检查该目录；如需全新演练，请换一个新的 `--task-dir`。
- **“其他标签页持有控制权”**：关闭或刷新持有控制权的标签页（其事件连接断开后控制权自动释放），再点击“获取控制权”。
- **显示“已达重试/刷新上限”**：表示达到有限上限，**不代表无货**。
- **显示“需要人工接管”/“需人工核验”**：出现验证挑战、限流、登录过期、页面无法识别、与计划不符或结果不明时，程序主动退让，由你本人处理。

## 限制（请务必阅读）

- **购买流程只有离线模拟。** 单独只读预检可识别官方公开入口；真实苹果结账流程、时段数据结构、拒绝/接受信号、预约保留时长、库存与容量均**未经验证**（需求中的 U02–U06 未解决）。界面中的模拟官网、延迟和时段都是虚构的。
- 基准数字是模拟数据，**不是**苹果官网性能、真实成功率或人工速度；“渲染时间”是在 Node 中生成状态卡片 HTML 字符串的耗时，不含浏览器排版/绘制。
- 跨进程独占已在本机 Windows 验证；代码还包含 Linux 抽象套接字路径，未在 Linux 实机验收。其他系统会拒绝启动（失败即关闭）。
- 本地标志无法保证服务端“恰好一次”；结果不明时以人工核验为准。
- Codex 已用真实浏览器操作本机模拟页面，验证自动全流程、两个标签页的控制权及在途暂停/恢复。这些证据只适用于本机演练界面。
