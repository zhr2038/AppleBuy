# Apple 直营店自提购买助手 — C-002 离线演练纵向切片

> **重要：本仓库当前只有离线演练。** 所有商品、门店、日期、价格、时段均为 **FAKE 虚构数据**；“模拟官网”使用的 `mock-v0` 契约是本项目**自行虚构**的，**不是** Apple 的页面或接口。运行时不会访问苹果官网，不会产生真实订单、付款或时段占用。真实结账与时段契约**尚未验证**（见下文“限制”）。

## 它演示了什么

一条命令跑完核心痛点流程，全程无需人工：

购买计划加载 → 观察时段列表 → 自动选择计划内优先级最高的时段 → 被模拟官网**明确拒绝** → 取**最新**列表（新代次、新引用）→ 自动改选另一个授权时段 → 被**明确接受** → 自动继续结账 → 到达模拟付款前终点（无正式授权时绝不提交）。

## 安装

无需安装任何依赖（零运行时依赖，未使用 npm 包）。只需要 **Node.js 24.16.0 或更高版本**（直接运行 `.ts` 源码，使用 Node 内置的类型擦除）。

```
node --version   # 应为 v24.16.0 或更高
```

## 运行

| 目的 | 命令 |
| --- | --- |
| 旗舰演练（拒绝→重选→接受→自动继续→终点） | `node src/cli.ts rehearse` |
| 运行全部 27 个场景并核对预期 | `node src/cli.ts rehearse --all` （加 `--quiet` 只看结论） |
| 运行指定场景 | `node src/cli.ts rehearse --scenario stale-list` |
| 列出场景 | `node src/cli.ts scenarios` |
| 开始前检查计划 | `node src/cli.ts check-plan --plan examples/plan.fake.json` |
| 决策级基准（模拟） | `node src/cli.ts bench --runs 200 --warmup 20 --seed 1` |
| 全部测试（实现测试 + 独立评审测试） | `npm test`，等价于 `node --test "test/*.test.ts" "review/*.test.ts"` |

退出码：`0` 全部符合预期；`1` 有场景不符合预期；`2` 用法或计划错误。

脱敏日志写入 `.local/runs/<运行编号>/journal.jsonl`，基准报告写入 `.local/bench/`。测试临时目录只在 `.local/test-runs/` 内创建，删除前会校验路径确实位于该目录内。

## 购买计划配置（`examples/plan.fake.json`）

| 字段 | 含义 |
| --- | --- |
| `fake` | `true` 表示虚构演练计划（界面会醒目标注 FAKE） |
| `fulfillment` | 只能是 `pickup`（直营店自提） |
| `quantity` | 只能是 `1` |
| `maxTotalCny` | 含税总价上限（元）；页面总价超过即拦截 |
| `products` | 授权的商品规格（型号/容量/颜色），可多个备选 |
| `stores` | 授权门店，`primary` 首选 / `backup` 备选 |
| `dates` | 授权日期（`YYYY-MM-DD`） |
| `windows` | 授权时间窗；整个时段必须落在某个窗口内 |
| `arrival` | 可到店时间范围；整个时段必须落在该范围内 |
| `priority` | 排序优先级，例如 `["date","store","window"]`；不按页面显示顺序 |
| `bounds` | 拒绝次数、刷新次数、单时段尝试次数、最小刷新间隔、查询失败次数、结果核实次数的上限（不能超过内置硬上限） |
| `paymentMethodLabel` | 付款方式**标签**（只作提示，不保存任何付款信息） |

缺失或放宽条件会被 `check-plan` 列为阻断项。运行开始后计划被**冻结绑定**（以计划哈希校验），外部修改不会扩大授权。

## 安全设计（摘要）

- **发送前复核**：每个改变状态的操作先写入“准备”记录，真正发给端口前再由引擎复核（暂停/接管/挑战/价格与计划/最新列表/正式授权/购买台账），通过才写入“发送”记录并调用端口；否则记录“取消（从未到达模拟官网）”。
- **同一时间只有一个在途操作**；结果不明时只做只读核实，**绝不自动重发**，核实无结论即停在“需人工核验”。
- **购买台账（引擎层保护）**：最终提交前先落盘；只要调用方**复用同一份日志/台账或同一个状态目录**，同一计划一旦有提交记录（含结果不明），重启或新运行都不能再次提交，需人工核验后用固定确认语清除（这一点由测试在共享状态下验证）。台账损坏时按“已消耗/不明”处理，不会当作空历史。
- **当前 CLI 不提供跨运行保护**：`rehearse` 的每次运行都是相互隔离、可重复的模拟场景，会在新生成的运行目录下创建各自独立的日志和台账；**没有**任务级持久化的独占/台账，也**没有**集成的“恢复运行”命令。因此连续两次运行同一场景（例如 `formal-submit-unknown`）会各自发送一次**模拟**提交并各自停在“需人工核验”。这是安全的离线演练，但**不能**当作“CLI 会阻止同一计划的新运行再次提交”。跨运行、跨进程的集成保证尚未实现，是 C-003 的必做项，在此之前不能认为真实适配已就绪。本项目不存在任何真实下单或付款能力。
- **日志**：哈希链 JSONL，字段白名单；截断、篡改、删除记录、计划不符或首条缺少计划绑定的日志一律拒绝恢复。邮箱、手机号、卡号、令牌等写入前即屏蔽为 `[已屏蔽]`。
- **网络防护**：演练时拦截所有非本机网络访问（socket 各种调用形式、fetch、DNS、UDP），并在传输前抛出。
- **真实适配器**：仅有一个永远抛错的占位类，CLI 未接入，引擎与运行器在结构上拒绝非 `mock` 端口。

## 常见问题

- **提示“计划无法使用”**：按列出的中文问题逐项修正计划文件。
- **提示“该计划已有提交记录”**：说明在**同一份台账/状态目录**中此前有（模拟）最终提交且结果可能不明。请先人工核验，确认后才能清除台账。注意：当前 CLI 每次运行使用独立的新台账，所以不同的 CLI 运行之间不会出现此提示（见上文“当前 CLI 不提供跨运行保护”）。
- **显示“已达重试/刷新上限”**：表示达到有限上限，**不代表无货**。
- **显示“需要人工接管”**：出现验证挑战、限流、登录过期、页面无法识别或与计划不符时，程序主动退让，由你本人处理。

## 限制（请务必阅读）

- **只有离线模拟。** 真实苹果结账流程、时段数据结构、拒绝/接受信号、预约保留时长、库存与容量均**未经验证**（需求中的 U02–U06 未解决）。基准数字是模拟数据，**不是**苹果官网性能、真实成功率或人工速度。
- **跨进程独占（A08）、DOM 级页面模拟和更完整的中文界面属于 C-003**，本切片未实现；同一计划请勿同时运行多个进程。
- **跨运行/跨进程的集成保护未实现**：重启与新运行不得再次提交的保护只在复用同一日志/台账（共享状态目录）时成立；当前 CLI 的每次运行都是隔离的模拟场景，没有任务级持久台账、所有权或恢复命令。这些是 C-003 的必做项，完成前不能认为真实适配已就绪。
- 本地标志无法保证服务端“恰好一次”；结果不明时以人工核验为准。
- 本切片已通过离线 M1 独立验收：86 项测试、27 个场景全部通过。验收范围与未完成项见 [Codex 独立验收记录](docs/reviews/C-002.md) 与 [当前状态及恢复点](docs/status.md)。
