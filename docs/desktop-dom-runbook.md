# 电脑上的完整自动演练

只需要电脑 Chrome 和已经安装的 Node.js 24.16.0。项目目录为 `E:\Apple Store`，无需新依赖或手机界面。

```powershell
node src/dom-demo.ts --task-dir .local/dom-desktop
```

打开终端打印的 `http://127.0.0.1:<端口>/`。页面明确标记 FAKE；核对一台虚构 Pro、256GB 黑色、¥9,999、虚构大连直营店及三天每天末档后，点一次“开始自动模拟下单”。这次点击仅授权本机虚构订单，不会访问苹果、预占取货时段或付款。

程序会实际点击原生 DOM 控件，自动加购、选择自提，处理前两天末档拒绝，并从最新列表改选下一天末档。第三天接受后，它继续填写虚构资料、选择模拟支付宝、创建一张未付款模拟订单，再通过另一项只读查单核对订单商品、数量、价格、门店和时段。运行关键路径没有在线模型。

页面出现“一张未付款模拟订单”且最终点击／订单均为 1，才算这次本机演练完成。真实官网取货日期和预占机制仍需另外验证；这个结果不能证明能抢到 Duo。当前真实订单授权已使用，不会再创建或支付。

场景菜单也可以在首次开始前选择超价、控件更新、最终回复丢失、结果始终不明或订单颜色错误。超价会在加购前停止；旧控件不能继续；丢失最终回复仅查单；订单条件不符或核实仍不明时停止，不重复提交。另开的标签页只读。暂停／停止阻止后续新命令，已经发送的浏览器命令可能继续完成，记录必须保留。

任务目录中保存购买台账、运行记录和进程所有权。刷新或重启保留记录并禁止再开始。虚构商店状态只保存在原标签页，重启页面不宣称已经恢复商店订单，也不会自动续跑。按 `Ctrl+C` 正常退出；进程结束测试不等于物理断电验证。不能通过删记录、新建任务或改计划重新提交一个结果不明的真实购买。

Chrome 只读连接组件在 `E:\Apple Store\web\chrome-connector`，四个文件无需构建。其权限仅为本人点击激活的 `activeTab` 和 `scripting`；无站点持续权限、后台脚本、Cookie、存储或网络请求。它只认识当前验证过的公开 Pro/Duo 商品路径，拒绝登录、账号和结账页面，不点击、不填表。安装与临时读取权限仍需本人在动作时明确同意；目前未安装。后续结账执行需要新的当前证据、准确实现与相应授权，不能把这个组件当作已经能下单。

新改动经过 Codex 检查，271 项测试通过，实际 Chrome 验证记录已保存；真实 Claude 额度恢复后还需按精确源码清单复审并达成一致。当前交付是功能候选，双方验收仍待完成。
