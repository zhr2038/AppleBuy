# C097 same-session pause and explicit continuation (Codex implementation)

R07/R08/A07/A09, direct Pro main-chain priority. Current Pause terminates the worker/browser and loses its context-bound buying identity. A transferred buyer becomes permanently readonly on reopening; that defeats ordinary pause/resume. Implement a distinct pause that retains the owned browser/context/kernel lease, aborts and drains current work, clears final consent and stops authentication auto-continuation. Explicit continue reuses the same task, re-observes pending results, never re-adds/re-checks out/re-submits because of pause, and does not extend task deadlines. Actual window/process close still performs full cleanup; an actual new context retains the prior readonly rules.

Acceptance: pause at REVIEW requires fresh consent and does not submit; pause during one sent checkout preserves pending truth and sends no pickup until explicit continuation; resume sends no second checkout/Add; readonly import never gains buying authority; repeated pause/resume and busy commands cannot start two actors; close after pause releases the original owner once. GUI Pause must send private pause IPC instead of killing the worker. No private input logs or new real purchase, no Chrome profile/cookie access, no fake production ledger. Codex runs meaningful failure reproductions and self-tests; combined pending C093/C096/C097 source requires actual original-session Opus5.5/xhigh review after provider reset, not old-map approval.
