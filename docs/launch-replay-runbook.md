# 开售页面回放说明

这是 C-007 的离线候选：只回放本机合成页面，未接入真实结账。C-007-R1 的修复尚待独立验收。

在 `E:\Apple Store` 运行：

```powershell
node src/cli.ts app --task-dir .local/launch-browser --plan examples/plan.launch.fake.json
```

同一任务同一时间只有一个标签页能控制。用电脑 Chrome 打开终端打印的地址后，**在同一个标签页**的地址栏把路径改成 `/launch`（例如 `http://127.0.0.1:端口/launch`）再回车；离开原页面会释放它的控制权，回放页随后自动获取。不要另开第二个标签页去操作同一任务：第二个标签页只读，不能控制。若已经开了多个标签页，先关闭其他标签页，再在要使用的那个标签页点“获取控制权”；控制权只在原标签页真正关闭后才能转移，不会按时间抢占。返回首页同理：在同一标签页打开 `/`。

页面默认展示当前进度、样本选择和候选；观察导入与异常验证折叠在下面。

1. 依次观察“尚未开售”“疑似维护文案”“尚未加载完整”“入口恢复”：区别页面状态，保留原任务和购买计划，旧引用失效。
2. 观察“日期与原生时段控件”：第一次看到完整日期列表时，冻结其中最先出现、可见且可选的至多三个日期（灰掉或隐藏的日期不算）。这些日期都在计划内才绑定；有不在计划内的日期时，范围仍冻结、不会改用后面的日期，并交给本人处理。每天只建议实际列表的末档。
3. 观察“重排并更换控件”或“原生日期单选与时段选择”：从当前 DOM 重新读控件；旧页面引用不能使用。
4. 观察“末档被移除”：不会自动改选当天更早档。观察“选择第四个日期”：不能扩大已冻结范围；刷新或重启后也不会滚动到第四个日期。
5. 每个合成样本由本机服务签发给当前控制的标签页，只能保存一次，且必须与签发时的计划版本一致；重复提交、换标签页或改计划后提交都会被拒绝，不会写入记录。修改计划后，页面会显示“回放记录属于计划 vN”，不会把旧观察改绑到新计划；改回原计划版本才能继续这份记录。
6. 暂停后退出原服务，再以原目录重启：暂停、冻结日期、末档和历史均保留；恢复后需要新观察。保存过程中断（例如断电）时，重启只会补完那一次已记录意图的保存；文件不一致、被回滚或另一进程同时写入时停止并保留原文件。
7. “日期缺少年份”“自提控件未选中”“商品不符”“要求登录”“要求确认条款”“限流”“访问限制”“无法识别的改版”会停止建议或交给本人处理。网络失败或没有维护文案的 503 不能当作无货或已确认维护。

“模拟提交结果不明”只设置虚构待核实证据，不发送订单。设置后，即使页面恢复、重启或换布局，也先核实，不能重发；本页没有清除这种证据的按钮。不要删历史或另建任务来重试同一真实购买意图。

命令行单独验收合成 AST：

```powershell
node src/cli.ts launch-replay --task-dir .local/launch-cli-check
```

首次执行输出 20 个场景、日期绑定、未知结果保留与外部网络调用数。再次使用已有待核实目录会拒绝继续，这是预期保护。CLI AST 不等于实际 Chrome DOM，也不等于 Apple 接受。

导入仅接受规定的脱敏语义字段，拒绝额外字段和个人资料。导入内容只在内存中预览一次：不保存、不产生候选、不冻结日期、不记录末档，也不能通过填写“来源”冒充合成样本。真实页面列表的完整性、年份、产品/规格/数量/价格/直营店绑定必须有独立当前证据，不能由合成样本迁移。

合成样本里的“取货门店”选择组和“总计（含税）”文字是本项目虚构的，没有对照当前官网核实。条件检查要求：页面上的商品行与计划的型号、容量、颜色完全一致（多出“Max”或颜色后缀都不算）；页面只有一个门店选择组，其中选中的门店在计划内，计划内的其他门店也没有出现在选择组之外；价格必须是带“含税”标签的总计，月供、“起”价或多个总价都会停止建议；隐藏或灰掉的控件不算。

10 月 2 日的 Pro 浏览器实跑已证明大连直营店自提及一张未付款订单；官网提示取货日期在付款后确定。这不是时段占用保证，也不证明 Duo 的拒绝、重选或开售机制。[真实验证与计时范围](reviews/Pro-Chrome-unpaid-pilot-20261002.md)

购买引擎的自动拒绝重选仍从首页演练：读取计划 → 第一天末档被明确拒绝 → 最新列表改选第二天末档 → 再拒绝 → 第三天末档被接受 → 继续到模拟付款前终点。回放页只负责页面观察与建议，没有第二个购买执行器。
