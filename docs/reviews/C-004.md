## Implemented scope and design

`node entry/cli.ts inspect` makes exactly one ordinary unauthenticated GET to the already observed official mainland Duo catalog. `--example` reads its already observed 512GB night-sky URL, solely as a public example. There is no arbitrary URL option, polling, retries, redirect following, session/account use, body retention, bag mutation, checkout port, slot reservation, order or payment method. The request uses GET, omits credentials, adds only an Accept header to the runtime's normal HTTP headers, and has an 8-second network deadline and 2-MiB body cap. Headers and error bodies are not printed or retained.

The separate entry executable preserves the existing offline application and its original network guard. It is not imported by `src/cli.ts`; the original 44 C-003 source hashes are unchanged. It uses the established Node 24 native TypeScript runtime, adds no dependency or lifecycle script, and cannot connect a public observation to mock formal authorization or an Apple mutation.

Only document-head title, target heading and explicitly visible public notices are recognized from HTML. Scripts are not executed. HTML alone leaves hydrated controls, pickup status and sale status unknown. The result is `PUBLIC_CATALOG_ONLY`, with purchase readiness permanently false. Title/heading changes, malformed structures, failed retrieval, authentication, access restriction, rate limits and redirects remain distinct; none means no stock.

`--snapshot` imports a narrow, sanitized public semantic browser observation offline. It does not automatically connect to or control a browser. The snapshot's source is explicitly an imported claim, requiring independent verification. Its exact fields are `schema`, `provenance`, `url`, `observedAt`, `renderComplete`, `title`, `productHeading`, `continuePresent`, `continueEnabled`, `pickupUnavailable`, and `notOnSale`. Schema is `applebuy-public-dom/v1`; provenance is `actual-browser` or `fixture`; URL must be one of the same two observed public entries. Time must be an actual UTC ISO observation time. Boolean pickup/sale fields are null when not observed. Extra fields, invalid dates/targets, contradictory controls, incomplete rendering and snapshots older than five minutes fail closed. The age check describes local observation age and does not prove server-side inventory freshness.

The preflight does not load a real user plan, validate a checkout SKU/store binding or infer any slot mechanism. `purchaseReady`, `realMutationsAvailable`, `checkoutSkuVerified` and `slotContractVerified` stay false on every path. Exit 0 means a bounded entry observation was recognized; it is not purchase readiness.
