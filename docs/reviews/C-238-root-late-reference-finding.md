# Root finding during the C239 source freeze

The C238347 candidate is not accepted by Root even if its outstanding review returns AGREE. Independent runtime reproduction found a functional regression in `DesktopCheckoutRuntime.executeOnce`: the new sent-final intercept immediately calls `checkNativeOrders(prior)`. When an originating same-context final has been sent but its receipt reference was not captured yet, `checkNativeOrders` returns `reference-missing` without observing the current receipt. Existing C236 logic could otherwise read that late receipt and pin its reference without resubmitting.

Actual private FAKE repro against the current production runtime returned reads0, actions0, referencePinned=false, state=reference-missing, followed by a failed assertion requiring the available original-context receipt to be read. The source is frozen while the unique C239 reviewer runs; no concurrent business edits were made.

Repair acceptance: only the same originating context with its sent final and missing reference may run the existing final-lookup controller to read the current receipt. A known hash goes directly to independent detail lookup. Readonly/rebound/foreign contexts with no hash must still remain unknown; they cannot attach another similar order. Preserve final/pending/history, no Add/Checkout/slot/final calls. Test R1 and R2, expired original action deadline, already-pinned different hash and foreign context. Then new exact manifest, regressions and one consolidated original-session Opus5.5/max review. Do not accept stale347 bytes from a later map or call this a quota failure.
