## 简化后的日常操作

1. 首次安装、更新或连接断开时，在已安装 AppleBuy 扩展连接购买通道。现有登记与权限无需每次重授。
2. 打开 Python 桌面窗口。默认 R1；官网已有有效取货资料可留空，缺失资料填一次，当前仅保存在会话内。
3. 点主按钮“开始 / 继续”。程序先读取原任务，按已有状态继续；登录或验证时按实际提示处理。
4. 真正到当前订单复核页，主按钮变为“接受条款并创建未付款订单”。核对本次信息与条款后点一次。
5. 提交后主按钮只用于订单核对。看到待付款回执不再提交；支付由本人决定，本程序不支付。

主界面只保留动态主按钮和暂停。R2、独立浏览器、演练、导入、旧任务恢复放在“高级 / 故障恢复”。它们保留原有记录与动作边界，不能清空历史或把未知下单结果当失败重试。暂停保留执行上下文；关闭或重启后的可恢复性仍受原任务限制，不能承诺所有阶段无缝恢复。

## 哪些已经自动，哪些还要补

| 环节 | 当前范围 |
| --- | --- |
| 商品、数量、价格、附加项与购物袋 | 已有程序校验与配置；本次实单从已有同款一台购物袋起步，没有重复加购 |
| 结账、门店、末档、取货资料、支付宝、复核 | 实单由程序推进；资料缺失时仍需要输入 |
| 原生待付款回执 | C236 新增只读识别与状态展示；需完成该版本审核和部署，不等于已在个人浏览器加载 |
| 同一张订单详情独立核验 | 本次由 Codex 完成，原生新详情的完整程序化核验仍待补；回执不能补造数量、金额或门店 |
| 下单前同账户已有待付款订单检查 | 本次由 Codex/本人核对，尚未全自动 |
| 普通登录 | 有效登录直接复用；此前 Codex 按本人委托登录，不等于程序已实现自动填写密码 |
| 验证码、验证挑战、新权限 | 需要本人按实际提示处理 |
| 资料持久保存 | 尚未实现；当前只会话使用，重开可能需重新填写缺失项 |
| 首次安装、更新重载、断线连接 | 当前仍需要一次本人连接，不保证浏览器重启后自动重连 |
| 当前条款与最终提交 | 一次明确按钮确认，随后程序提交一次；不自动接受未知条款 |
| 支付 | 留给本人，不做自动支付 |

C236 将“回执说等待付款”与“程序独立核验完整订单详情”分开显示。仅在本次提交的原动作有效观察窗口内，匹配原生回执才显示等待付款；迟到回执只确认发现订单，当前支付状态仍待核验。公开状态仅含订单参考的哈希，不导出带客户邮箱的订单链接。
