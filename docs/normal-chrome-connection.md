# 使用你正常登录的 Chrome

这条通道让桌面程序通过 AppleBuy 扩展读取正常 Chrome 的官网购物袋，不需要在程序新开的浏览器反复登录。当前版本只读，不会加购、结账、选时段或创建订单。

本机通道需要给这一个 AppleBuy 扩展增加可选的 `nativeMessaging` 权限，并登记当前 Windows 用户的 `com.applebuy.readonly` 主机。主机只允许你提供的那个扩展 ID，不能使用通配来源；不复制个人 Chrome 的 Cookie 或浏览器目录。完成代码复审和这次具体授权后，Codex 才执行本机登记。

1. 在 Chrome 扩展管理中，给原 AppleBuy 点一次“重新加载”，保留原来的扩展和任务记录。
2. 从原 AppleBuy 图标打开入口，点“连接桌面程序（只读购物袋）”。
3. 在新开的连接页点“本人允许本机连接（仅只读购物袋）”，由你本人处理 Chrome 权限提示。保留这个连接标签页，关闭它会断开本机连接。
4. 在桌面程序点“读取正常 Chrome 购物袋（只读）”，也可用 `Ctrl+Alt+C`。这一步读取的是当前购物袋页面，不核实登录或账户身份，游客也可能看到空购物袋。

程序会新开一个自己的后台官网购物袋标签页，只读取页面结构，核对两次稳定结果，然后关闭自己的这个标签页，不关闭你的原网页。只有原本已经允许的官网主机能读取；缺权限或页面不明会停止。它不读取密码、验证码、原始网络请求或订单客户资料。

若提示购物袋为空，旧的未知加购仍保留，不因此再加一台。提示需要登录时，请本人在正常 Chrome 完成官网登录；不要发密码或验证码。连接失败不会另开购买流程。

撤销通道时，关闭连接页，并在 Chrome 的 AppleBuy 扩展设置撤销本机通信权限。需要移除本机登记时由 Codex核对当前登记归属后删除自己的登记；不要删除个人浏览器目录或旧购买记录。

目前缺少实际 Chrome 安装后的完整通信、正常登录识别、空袋重新购买和未付款订单证据。原有结账目标继续保留，不能把本机通信测试当作已自动下单。
